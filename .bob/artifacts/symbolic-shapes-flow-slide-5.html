Symbolic Shape Support — Compile-time Flow

From mark_dynamic to SDSC JSON emission  ·  torch-spyre

User code
before compile
mark_dynamic(tensor, dim=0, min=32, max=256)
Dynamo's ShapeEnv creates a sympy symbol s97 and records its range [32, 256].
From this point, any size/stride that depends on dim 0 is a sympy expression, not a plain integer.
ShapeEnv lives only during compilation — it will be gone by SDSC codegen time.

Bound Extraction & Bucket Computation
finite_upper_or_none(s97) → reads ShapeEnv upper bound → 256
_user_min_or_none(s97) → reads ShapeEnv lower bound → 32

compute_max_size(s97) → tries finite upper first; falls back to optimization_hint if not set

Two helpers used in every core-split decision:
_effective_size(d0, it_space, meta) → max=256 (worst-case footprint for span checks)
_valid_divisor_basis(d0, it_space, meta) → gran=32 (split must divide granularity, not max)

compute_ops.py
:588–604, 1191–1237
generate_sdsc() — SDSC JSON Emission
Register dim symbol before address symbols (IDs must never collide):
  dim_local_symbols = { "s97": -1 }  ← negative ID, no HBM address

Write JSON key 1 — dimToSymbolMapping_:
  { "M": [-1] }
  → tells runtime: read actual tensor size and bind it to symbol -1

Write JSON key 2 — symbolicDimInfo_:
  { M: { maxSize_: 64, granularity_: 8 } }
  → per-core values (256 / 4 splits = 64, 32 / 4 splits = 8)
  → tells runtime: value must be ≤ 64/core and a multiple of 8/core
